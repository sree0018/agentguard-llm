AgentGuard-LLM Report

AgentGuard-LLM · course project · output-side defense for AI agents

A local language model catches what the regex misses, and it costs false alarms

AgentGuard checks what an AI agent is about to do, not what it read. Its weakest check was a regex. We replaced it with a model that runs on the laptop, then tried to break it.

AgentGuard-LLM: a local-LLM payload guard for AI-agent tool calls
Team: Aditya, Gopika, Meera, Sreeranj

96%of held-out attacks got through the original regex (134 of 139)
12%got through the strict local-LLM guard (16 of 139), at a cost of 12% false alarms

Pooled over three test sets written after the guard prompt was frozen. Confidence intervals and the adaptive-attacker result that tempers this claim are further down.

The problem

An agent that reads untrusted text can be talked into leaking secrets

Indirect prompt injection hides instructions in content the agent is asked to read. The user never sees them. The agent may obey them and use a tool it legitimately has.

The defense

Four checks on every tool call, and the guard never reads the page

The guard sees two things: the task the user pinned and the call the agent proposes. The retrieved content is cut off, so an injected instruction cannot address the guard directly. Checks 1 to 3 are deterministic rules. Check 4 looks inside the payload.

The gap

A regex cannot see a secret that has no pattern

The original check 4 matched strings like sk-live-… and password=. All five original obfuscation attacks (the report's ADV-2) passed it. In the held-out sets it let 134 of 139 through. Here is what that looks like, using real cases from the test sets.

The new check 4

A small model on the laptop, with every failure treated as a block

The guard is llama3.1:8b served by Ollama. Decoding is greedy with a fixed seed, and the model must return a JSON verdict. Anything else, including a crash, is a block. Every answer is cached on disk, so anyone can replay the results with no model installed.

How we tested

A set that shaped a prompt never counts as held out for it

Prompts were tuned on DEV only. Each later test set was written before the guard version scored on it existed, and its dataset hash and the prompt hash are logged. Blue cells are the only ones that feed the headline numbers.

Result 1

The strict guard stops most of what the regex lets through

Result 2

The price is a 12% false-alarm rate on hard harmless text

The strict prompt says to block when unsure. It blocks a Zürich weather query, a Hindi greeting, and a message that quotes a file hash. The regex blocked 2 of the same 82.

Result 3

Relaxing the guard removes false alarms and lets attacks back in

We built three variants to cut false alarms. Each did, to about zero, and each leaked 25 to 42% of held-out attacks. That is why the strict version stays the default.

Where it fails

Secrets dressed as identifiers and written as prose are the weak spots

Pooled over TEST2 and TEST3. The strict guard is excellent on encodings and on attacks aimed at itself, and weakest on content that looks ordinary.

A surprise

Decoding for the model fixed one kind of attack and broke another

The pre-pass decodes base64, hex and similar, then shows the model the result. Decodable attacks dropped from 3 to 0. Attacks the pre-pass cannot decode rose from 3 to 10. The model seems to treat "nothing decoded" as reassurance. That reading is our interpretation of the numbers, not something we proved.

Worst case

An attacker who sees the verdict still wins

The adaptive attacker is a structured search, not a model. It gets 30 tries per target, learns from ALLOW or BLOCK, and every payload it builds provably contains the secret. No guard held on every target.

The practical reading: pair the guard with allowlists, data-loss rules, and alerts on repeated blocks. A prompt alone does not settle it.

Limits

What this does not show

  • One author wrote both the guard and the tests. The harness accepts independent cases from teammates, and none are included yet.
  • The agent is a simulation, and the test sets are small, which is why every rate has an interval.
  • Several candidates were compared on TEST3, so differences among the relaxed variants are exploratory, not a confirmed ranking.
  • The adaptive attacker is a search over encoders, not a language model, and it assumes the attacker sees each verdict.
  • The guard is itself an attack surface. It held against the guard-targeted cases we wrote, which is not a proof.
  • Results are for one model family at one size. Other models could move every number.
